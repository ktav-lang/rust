## Найденная Проблема

### R11-F1. P2: false positive quote-флага не безвреден для SplitQ

Места: `src/parser/inline.rs:40`, `:2320`, `:2341`, `:2360`;
`src/thin/inline_emit.rs:303`.
Связанные тесты: `src/parser/tests.rs:1560`, `:1966`, `:2846`.

После оптимизации `has_quotes` вычисляется на всём корневом inline body
и передаётся неизменным во вложенные объекты. Кавычка в соседней паре,
включая обычный строковый value, переключает quote-free потомок с
`SplitFast` на `SplitQ`. Эти два пути не эквивалентны на EOF после
whitespace в незавершённом dotted key.

Результаты одинаковы у `parse`, `parse_strict`,
`from_str::<serde_json::Value>` и `parse_events`, в обоих профилях:

| Документ | Фактическая категория | Ожидаемая категория |
|---|---|---|
| `{a: {b. }}` | `MalformedInlineCompound` | `MalformedInlineCompound` |
| `{a: {b. }, q: '}` | `EmptyKey` | `MalformedInlineCompound` |
| `{q: ', a: {b. }}` | `EmptyKey` | `MalformedInlineCompound` |
| `{"a": {b. }}` | `EmptyKey` | `MalformedInlineCompound` |
| `[{b. }, ']` | `EmptyKey` | `MalformedInlineCompound` |
| `{a: {b.}, q: '}` | `MalformedInlineCompound` | `MalformedInlineCompound` |

Замена `'` на `"` или backtick в соседнем value сохраняет расхождение.
Вместо SPACE после `b.` его вызывают также TAB и U+2000. Добавление
trailing comma после `b. ` возвращает `MalformedInlineCompound`.
Парный вариант `root: {a: {b. }, q: '}` воспроизводит тот же дефект.

Причина:

1. `SplitQ` при `in_key && seg_start` вызывает `skip_segment_ws`.
   После точки и завершающего whitespace получает `EofAfterWsSkip`.
2. В `split_top_level` непустой остаток последней пары немедленно
   превращается в `EmptyKey`, до поиска separator.
3. `SplitFast` не делает этот whitespace-skip, возвращает сегмент
   `b. ` обычным путём. Его caller не находит `:` и возвращает
   `MalformedInlineCompound`.

По §6.12 отсутствие separator внутри закрытого inline Object есть
`MalformedInlineCompound`; §5.8.2 отсылает к семантике §5.3, где
separator проверяется до key validation. Нельзя приравнивать `b. `
без separator к `b.: 1`: второй случай действительно имеет пустой
сегмент ключа и MUST оставаться `EmptyKey`. Этот положительный
контроль тоже проверен, как и допустимый `{a: {b: 1, }, q: '}`.

Изменение `acbc34a` расширяет достижимость старого дефекта `SplitQ`.
В исходнике `acf62a4` dispatch проверял кавычки текущего body, поэтому
quote-free `b. ` шёл через `SplitFast` независимо от соседей наверху.
Это вывод из git diff и потока вызовов; отдельный старый бинарник в
этом раунде не пересобирался. Сам ошибочный oracle существовал раньше:
`r3f1_split_top_level_dotted_key_trailing_ws_is_empty_key` прямо требует
`EmptyKey` для пары без separator. Поэтому `{q: ', b. }` и `{"b". }`
уже были неверными случаями на quote-aware пути. Прежнее принятие
этой части R3 требует поправки: отсутствие panic правильно, выбранная
категория нет.

Почему зелёные проверки это пропустили:

- Новый `r10f1_root_quotes_threaded_over_quotefree_descendants` проверяет
  только корректные пары. Ошибочный EOF-переход там не достигается.
- `memo_bounds_are_a_pure_memo_of_the_live_dispatches` сравнивает memo
  с поиском/сканированием closer. Он не доказывает равенство результатов
  `SplitFast` и `SplitQ` при обоих значениях передаваемого флага.
- Старый R3-тест закрепляет ошибочную категорию. Совпадение нескольких
  API тоже не является независимым oracle: они используют общий helper.

Исправление: унифицировать обработку последнего pair segment и дать
caller проверить separator до dotted-key validation. EOF после точки
не должен самостоятельно означать `EmptyKey`; при этом нужно сохранить
безопасность индексов и допустимость trailing comma. Исправить oracle
R3 и добавить публичные проверки категорий для вложенного quote-free
body при кавычках в ключе предка, соседнем value и соседнем array item,
а также варианты SPACE/TAB/Unicode whitespace и положительные контроли.

Не возвращать ради этого полные quote-prescan на каждом уровне: их
устранение полезно. Передача консервативного признака допустима после
доказательства эквивалентности выбранных путей, включая ошибки.
В комментариях и [отчёте R10-F1](2026-09-09-r10f1-quote-prescan-cost.md)
нужно исправить и логическое обоснование: отсутствие кавычек в root
гарантирует их отсутствие у потомка, но наличие в root не гарантирует
наличия в каждом потомке. Утверждение о byte-identical split сейчас
неверно; пустой diff конечного корпуса этого не доказывает.

### Стоимость Quote-Prescan

`scan_unescaped_colon` теперь проверяет quote-opacity префикса
кандидатного separator, не всего value. После quoted span поиск
продолжается с позиции за closer. При отсутствии следующего кандидата
остаётся полный slow fallback для различения `Absent` и
`UnterminatedQuote`; это отдельный завершающий проход, а не повторение
по каждому уровню вложенности. Проверены quoted colons в нескольких
сегментах, отсутствие separator и value-side `a: b."unterm: 2`.

Повторно выполнен штатный детерминированный тест
`ix_probe_r10f1_quote_prescan_counters`, без timing loops.
`hq_bytes` есть сумма длин диапазонов, переданных в `has_quote_bytes`,
а не время, аппаратные byte loads или счётчик аллокаций. Для семейства
`deep_chain_leaf(D, M)` результаты owned/event-путей совпали:

| Длина листа M | Глубина D | Размер документа | hq_bytes |
|---|---|---|---|
| 512 | 1 | 520 | 1039 |
| 512 | 4 | 535 | 1075 |
| 512 | 8 | 555 | 1123 |
| 512 | 32 | 675 | 1411 |
| 512 | 64 | 835 | 1795 |
| 8192 | 8 | 8235 | 16483 |
| 65536 | 8 | 65579 | 131171 |

В этой quote-free семье наблюдаемые значения равны `2*M + 12*D + 3`:
длинный лист больше не проверяется заново на каждом уровне. Анализ
вызовов и counters подтверждают устранение прежнего `Omega(M*D)`
механизма в этой стадии; остаётся `Theta(M+D)` объёма prescan.
Регрессионные scaling-тесты также прошли в debug/release.

Это не доказательство `Theta(N)` для всего parser: memo по-прежнему
сортирует C границ и ищет их бинарным поиском, с совокупным
`O(C log C)` компонентом. Рекомендация оставить компактный sorted `Vec`
не пересматривается без отдельного замера альтернатив. Проценты
ускорения, маргинальная цена lookup и отсутствие каких-либо других
узких мест из этих counters не следуют.

### Аллокации Writer

`src/render/canonical.rs:350` больше не разбивает строку только ради
обратного соединения. Устранены аллокация и `O(L)` временных ссылок
для L строк; output `String` по-прежнему занимает память пропорционально
результату. Никаких аллокаций для передачи root quote-флага не добавлено.

Canonical fixtures проверяют точные bytes. Дополнительно в debug/release
проверены roundtrip и idempotence для обычного multiline, ведущей и
замыкающей пустых строк, целиком пустых строк, mixed TAB/SPACE и
U+2000/U+2001 stripped fallback. Отдельный allocation profiler и
временные измерения writer не запускались. Новых обязательных
переписываний hot paths сверх исправления R11-F1 не предлагается.
