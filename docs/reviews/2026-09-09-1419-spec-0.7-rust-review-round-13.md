## Найденные Проблемы

### R13-F1. P2: raw Ryu для f32 не является нормализованным payload parser

Места: `src/ser/value_serializer.rs:29`, `:36`, `:99`;
parser: `src/parser/classify.rs:117`, `:521`,
`src/parser/inline.rs:434`, `:458`;
контракт: `src/value/value.rs:20`, `:33`, `:84`;
пробел в тестах: `tests/float_value_consistency.rs:58`, `:120`.

Исправление убрало `.0` перед экспонентой и теперь кладёт в `Scalar`
непосредственно `ryu::Buffer::format(v)`. Для `f64` это совпадает с
parser. Но в `float_scalar_f32` Ryu получает `f32`, а оба parser-пути
читают десятичную запись как `f64`. Форматирование Ryu для этих типов
использует разные пороги выбора decimal/scientific notation.

Минимальный воспроизводитель через публичный API:

```rust
let source = std::collections::BTreeMap::from([("x", 1e-6_f32)]);
let before = ktav::ser::to_value(&source).unwrap();
let text = ktav::emit_canonical(&before).unwrap();
let after = ktav::parse(&text).unwrap();
assert_eq!(after, before);
```

`before` содержит `Float("0.000001")`, canonical text равен
`x: 1e-6\n`, а `after` содержит `Float("1e-6")`. Assertion падает.
С `render` текст равен `x: 0.000001\n`, но parser всё равно хранит
`Float("1e-6")`. Проблема воспроизводится и для Array root.

Подтверждённые payload-различия:

| Значение f32 | Payload из `to_value` | Payload после roundtrip |
|---|---|---|
| `1e-6` | `0.000001` | `1e-6` |
| `-1e-6` | `-0.000001` | `-1e-6` |
| `2.345678e-6` | `0.000002345678` | `2.345678e-6` |
| `9.999999e-6` | `0.000009999999` | `9.999999e-6` |
| `1e13` | `1e13` | `10000000000000.0` |
| `-1e13` | `-1e13` | `-10000000000000.0` |
| `1e14` | `1e14` | `100000000000000.0` |
| `1e15` | `1e15` | `1000000000000000.0` |

Причина проверена по исходникам закреплённого Ryu `1.0.22`,
`src/pretty/mod.rs`: `format32` использует верхнюю decimal-границу
`kk <= 13` и нижнее условие `-6 < kk`, а `format64` соответственно
`kk <= 16` и `-5 < kk`. Обещание в комментарии helper, что raw Ryu
даёт ровно хранимую parser форму, для `f32` поэтому неверно.

Всего проверены 23 значения `f32`, каждое для Object/Array и
canonical/pretty: 92 сочетания, из них 32 имеют неравные `Value`.
Вывод debug/release совпал. Отдельный режим с обязательным
`assert_eq!` действительно завершился ошибкой на первом `1e-6_f32`
в обоих профилях; успешные числовые проверки не заменяют этот assertion.

При этом во всех 92 сочетаниях обратный `from_str::<...f32>` сохраняет
биты. Все 46 canonical outputs принимаются `parse_strict` и
идемпотентны при повторном canonical emit. Это не потеря точности и не
неправильные canonical bytes §5.9.8. Дефект в согласованности Rust API:
`Value::PartialEq` сравнивает строки, а библиотека сама создаёт разные
представления одного числового значения. Сравнение документов получает
ложное различие; нарушается заявленная нормализованная форма `as_float`.

Новые тесты проверяют правильное свойство равенства `Value`, но выбирают
`1e20`, `1e-20`, `0.1`, `16777216.0`, где формы Ryu совпадают. Поэтому
зелёные тесты не означают полного закрытия R12-F1. Добавить граничные
семейства из таблицы, соседние контрольные `1e-5`, `1e-7`, `1e12`,
`1e16`, оба знака, Object/Array и оба writer. Числовые биты и exact
canonical bytes проверять дополнительно, а не вместо равенства `Value`.

Исправление: нормализовать хранимый `f32` payload по тому же binary64
представлению, которое создаёт parser. При сохранении нынешней
политики serde это означает сначала получить shortest decimal для
`f32`, затем нормализовать его как parser-число. Не подменять это
незаметно форматированием `v as f64`: такое расширение сохраняет точное
двоичное значение исходного `f32`, но меняет нынешнее десятичное
представление, например для `0.1_f32`. Сохранить `NonFiniteFloat` и
знак нуля; промежуточный heap `String` для нормализации не требуется.

Это остаток прежнего дефекта, а не новая регрессия числовой точности.
R12-F1 закрыт для прежних `f64`-воспроизводителей, но не целиком.

### R13-F2. P3: rustdoc-ссылки не проверяются существующими quality gates

Основные места: `src/thin/mod.rs:103`, `src/render/canonical.rs:409`.

`cargo doc --locked --no-deps` завершился с кодом 0, но выдал warning
для ссылки `from_str` в публичном `ParseEvent`: в этом модуле такого
имени нет, нужна ссылка на `crate::from_str`.

С `--document-private-items` получилось 9 warnings. Среди них новая
ссылка `Cow::Borrowed`: функция использует полный путь
`std::borrow::Cow`, но `Cow` не импортирован для разрешения ссылки.
Остальные семь warnings относятся к ссылкам в
`src/parser/classify.rs:637`, `src/parser/inline.rs:683`,
`src/thin/event.rs:3`, `src/thin/event_deserializer.rs:1`, `:5`, `:8`,
`src/thin/event_parser.rs:2`, включая прежние имена модулей `value`,
`streaming`, `parser` и недоступный в обычной doc-сборке test-only probe.

Это документационный дефект низкого приоритета, не ошибка runtime
или сборки crate. Новая ссылка на Cow относится к `c568615`, остальные
предупреждения относятся к ранее существовавшим комментариям.
R12-F3 про неверную грамматику комментариев/root kind этим не открывается:
его содержание исправлено, здесь другая проблема.

Исправление: использовать корректные item paths либо обычные code spans
для удалённых/test-only сущностей. Проверять документацию отдельно с
lint `rustdoc::broken_intra_doc_links` в режиме deny; для полного
покрытия внутренних комментариев нужен `--document-private-items`.
`fmt`, `clippy -D warnings` и обычные тесты не выполняют эту проверку.
В просмотренных CI/release workflows doc-gate отсутствует.

## Закрытие Раунда 12 И Производительность

**R12-F1 частично закрыт.** Все 13 прежних `f64` случаев, включая
минимальный subnormal, максимальное конечное число, оба нуля и пороги
notation, прошли с exact canonical bytes, strict acceptance, проверкой
битов и равенством `Value` в debug/release. Прежние три `f32` случая
и Array `1e100_f64` теперь тоже имеют равные payload. Оставшийся
механизм для `f32` описан в R13-F1.

**R12-F2 закрыт в предложенном минимальном объёме.**
`canonical_float` возвращает `Cow::Borrowed` для нуля и decimal-области:
`s.to_string()` на этом пути больше нет. Writer копирует срез в свой
output buffer; strict parser сравнивает срез без временного owned
текста. Это применено к обоим callers: обычной и inline-классификации.
`ValueSerializer` также больше не создаёт промежуточный `String`
перед `Scalar`, используя стековый Ryu buffer напрямую.

Для G обычных Float устранены G временных материализаций в
`canonical_float`; асимптотика обработки остаётся `O(G)` при
фиксированном binary64-домене. В scientific-ветке остаются два
промежуточных `String` (`format!` и `normalise_scientific`,
`src/render/canonical.rs:430`, `:461`). Это следующий локальный
кандидат: нормализовать готовый буфер на месте или писать в output
buffer, сохраняя strict callers. Он не считается новой находкой:
раунд 12 явно допускал оставить эту ветку owned.

**R12-F3 закрыт.** Rustdoc теперь правильно описывает Object/Array
root и `##`; отдельный `#` обозначен обычным содержимым. Два новых
integration-теста прошли, как и прежние внешние примеры обоих вариантов.

Изменения этого раунда не затрагивают индекс inline-границ или arena.
Компонент `O(C log C)` для сортировки/поиска C границ и резерв arena
от размера исходного текста (`src/lib.rs:170`) остаются прежними
профильными кандидатами. Нового основания менять структуры данных
или заявлять улучшение общей асимптотики не получено. Промежуточный
multiline `Vec` не возвращён. Проценты ускорения и фактические числа
allocator calls не заявляются: здесь анализ кода, не benchmark.
