## Decisions

- **Removed the invented inline raw-marker branch rather than keeping working behavior.** The adjudicating agent's ruling was verified against `spec.md:579` (`<inline-item-list>` derives only `<inline-value>`), `:641-650` (the `::` branch is scoped by normative text to the inline-PAIR position), `:655-659` ("Any other first byte makes the value an `<inline-scalar>`") and `:1573`. Rejected the alternative of treating existing behavior as settled — that is exactly how it survived earlier rounds. Verified no spec fixture puts `::` inside an inline array and that round-trip works via the § 5.9.6 line form, so this is a conformance fix, not a language change. Documents relying on the old stripping do change meaning.
- **Accepted R8-F2's larger fix (killing both fast-mode quirks) over a narrow one.** Making the fast and quote-aware machines byte-identical on quote-free slices lets the memo's purity condition become unconditional. Rejected conditioning memo recording on quote presence — the review explicitly forbade it because it would re-scan quote-free subtrees of quote-bearing bodies and restore the O(N·D) cost #161 removed. 8 corpus inputs changed error category; all were already invalid, all uniform across four entry points, zero OK↔ERR flips.
- **Kept the `InlineBounds` index unchanged after measuring it (#168).** Counters showed the sort is O(C) not O(C log C) on all-sibling shapes (4095 comparisons at C=4096, because pop order is already opener-ascending and pdqsort detects the run), 100% lookup hit rate, and ~0.05 index ops/byte on mainstream documents. A bypass-switch A/B showed removing the memo is slower on every shape and faster on none. Rejected all three replacements the review floated.
- **Merged agent branches as squashed, rewritten commits rather than cherry-picking their history.** R8-F1's branch had three `wip:` commits including a non-compiling state, which breaks bisect. Each merge is one commit whose message states the evidence I personally reproduced.
- **Chose to start #169 before #168 despite the lower id.** They conflict on `src/parser/inline.rs`, so they had to be sequential, and #168's acceptance is a measurement this machine could not support well; #169 was a confirmed defect with no such dependency.
